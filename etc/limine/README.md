# Limine theme: reference only, never symlink

`theme-header.conf` here is a copy of the top of `/boot/limine.conf` (OLED
black + red, matching the sddm/plymouth theme). It's reference/history
only - **`/boot/limine.conf` must never be a symlink into `~/dotfiles`**.
Limine reads it straight off the EFI System Partition before Linux boots;
`/home` doesn't exist yet at that point, so a symlink there would likely
just fail to boot at all (worse than the sddm `/home`-mount-timing issue).

The rest of `/boot/limine.conf` (everything after this header) is
auto-generated by `limine-entry-tool` / `limine-snapper-sync` on every
kernel/snapshot change - don't touch it, and don't include it here.

## Reapplying

`omarchy refresh limine` resets the header back to the stock green theme
(copies from `/usr/share/omarchy/default/limine/limine.conf`, then
regenerates entries). If that ever gets run, redo this manually:

```bash
sudo bash -c '
  tail -n +21 /boot/limine.conf > /tmp/limine-entries.conf
  cat ~/dotfiles/etc/limine/theme-header.conf /tmp/limine-entries.conf > /boot/limine.conf
  rm /tmp/limine-entries.conf
'
```

(Adjust the `+21` if the header's line count changes - it should match
`wc -l < ~/dotfiles/etc/limine/theme-header.conf` plus one.)

No rebuild step needed - Limine reads the plain text file directly at
boot.
